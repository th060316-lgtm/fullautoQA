## MANAGEMENT GATE

### What it measures
`evaluate_management()` (`management_evaluator.py:546-736`) reads one bundle (`management_evidence.json`, produced only by `phase3_run_evidence.build_management_evidence`, `phase3_run_evidence.py:311-341`) and emits **REQUIRED** rows; the domain is PASS only if every REQUIRED row is PASS (`management_evaluator.py:161-174`).

REQUIRED rows = `management.evidence_kind` + `management.measurement_coverage` + the REQUIRED subset of `SIGNAL_GATES` (`management_evaluator.py:110-155,289-307`):
`reproducibility`(true) · `fresh_run`(true) · `target_generation_integrity` · `one_click`(true) · `manual_intervention`(false) · `no_admin`(true) · `offline`(true) · `integrity`(true) · `residual_risk`(present, no blocker).
The six numeric measurements (`cpu_percent, ram_mb, handles, runtime_seconds, disk_bytes, evidence_bytes`) are **ADVISORY** unless a threshold is configured, in which case they become REQUIRED and enforceable (`management_evaluator.py:581-583`); with no threshold they stay INCONCLUSIVE-but-advisory (`:340-347`) — the project deliberately invents no limits.

### What it requires to emit PASS
1. `evidence_kind == 'real_game'` → identities certifying a real target **and** `run_mode=='target'` **and** a PASS `*.launch` row (`phase3_run_evidence.py:313-323,118-122`).
2. `measurement_coverage` PASS → all six metrics present (`management_evaluator.py:102-104,598-614`); `cpu_percent` needs ≥2 samples per pid with `cpu_seconds` (`phase3_run_evidence.py:62-83`; sampled at `windows.py:152`, `windows_runner.py:358`).
3. `reproducibility == true` → the **only** producer derives it from `*.seed_replay` rows and stamps `scope:'same_run_seed_replay'` (`phase3_run_evidence.py:252-262`); the evaluator then forces `INCONCLUSIVE / MANAGEMENT_REPRODUCIBILITY_SCOPE_LIMITED` (`management_evaluator.py:427-434`). Repo test asserts this: `TESTS/test_management_hq.py:469-484`.
4. `fresh_run` → `FULLAUTOQA_FRESH_EXTRACTION=1` + id (`phase3_run_evidence.py:264-265,320`; set by `source/START_QA.cmd:4-9`).
5. `one_click` → `FULLAUTOQA_START_QA=1` **and** `reproduction.json` exists (`phase3_run_evidence.py:266-270`; written at `windows_runner.py:653`).
6. `manual_intervention == false` → requires `FULLAUTOQA_AUTOMATED_CONTROLLER=1` (`phase3_run_evidence.py:272-277`; set only by the series controller, `acceptance_targets/run_series.py:182`).
7. `no_admin == true` → `IsUserAnAdmin()==False` on Windows (`phase3_run_evidence.py:287-292`; the local runner refuses elevated sessions, `RUN_LOCAL_COMPLETION.ps1:657-660`).
8. `offline == true` → PowerShell `Get-NetAdapter` snapshot returns MEASURED with **zero** Up non-loopback-IP adapters (`phase3_run_evidence.py:125-192,279-285`). Repo test: `TESTS/test_phase3_integrated.py:164-182` (adapter Up ⇒ no offline signal).
9. `integrity == true` → `preflight.core` PASS and every PASS row's evidence file exists (`phase3_run_evidence.py:218-242,294-296`).
10. `target_generation_integrity` PASS → bundle generation/fingerprint must match the frozen identity (`management_evaluator.py:482-540`; frozen identity injected at `coordinator.py:391-397`).
11. `residual_risk` with no blocker → the producer lists **every REQUIRED non-PASS row** as `severity:'blocker'` (`phase3_run_evidence.py:298-307`), which `_blocking_residual_risk` turns into FAIL (`management_evaluator.py:402-414`).

### Can a standard, non-admin, offline Windows run of the real game satisfy it?
**No — the gate cannot turn PASS by design, independent of the machine.**

I executed the real producer + evaluator on a faithful real-target bundle (non-admin, fresh extraction, controller marker, all measurements present, `*.launch` PASS, `*.seed_replay` PASS):

* without a `.seed_replay` row → `NOT_RUN / MANAGEMENT_SIGNAL_ABSENT` (`management.reproducibility` absent — and **neither** acceptance target declares `verify_seed_replay`: `codegeas/profile.json` and `politicstrasport/profile.json`; only `source/PROFILES/fixture_procedural.json:312` does).
* with a `.seed_replay` row → `NOT_RUN / MANAGEMENT_IDENTITY_UNAVAILABLE`, and `management.reproducibility = INCONCLUSIVE / MANAGEMENT_REPRODUCIBILITY_SCOPE_LIMITED`.

Every other observation (evidence kind, measurements, fresh_run, one_click, manual_intervention, no_admin, integrity, target generation) **is** producible by a standard-user offline run; `offline` is producible **only** if the machine has literally zero Up non-loopback-IP interfaces (a wired NIC left enabled with an APIPA address counts as Up ⇒ signal absent). The single structural blocker is #3 — the producer can only emit a scope the evaluator rejects. The evaluator itself *can* PASS (`management_evaluator.py:435-440`; `TESTS/test_management_hq.py:440-445` asserts `report.status=='PASS'` with `reproducibility: True` unscoped) — so the gap is on the **observer/producer** side, not in the evaluator.

## SALES GATE

### What it measures
`evaluate_sales()` (`sales_evaluator.py:471-714`) reads `sales_evidence.json` (produced only by `phase3_run_evidence.build_sales_evidence`, `phase3_run_evidence.py:358-396`) and evaluates 10 REQUIRED rows: `cold_start_session`, `cold_start_provenance`, the four phase gates `first_30_seconds / first_5_minutes / product_shelf_test / communication_readability` (`sales_evaluator.py:69-80`), `product_description_independent`, `what_game_summary`, `nontechnical_report`, `human_test`.

### What it requires to emit PASS
* A session flagged `cold_start` with ≥1 review phase and recorded provenance (`sales_evaluator.py:486-526`).
* **Each** phase row must carry an explicit verdict **or** a findings list with no blocking finding (`sales_evaluator.py:348-373`); a phase record with neither → `NOT_RUN / SALES_OBSERVATION_INCOMPLETE` (`:374-379`).
* `product_description_independent` / `what_game_summary` PASS only when the audience summary is `GENERATED` with non-empty, name/IP/price-blind descriptions (`sales_evaluator.py:555-592`; `audience_summary.py:42-92`).
* `nontechnical_report` PASS requires `communication_readability == PASS` (`sales_evaluator.py:594-619`).
* `human_test` PASS requires `reviewer.kind == 'human'` (`sales_evaluator.py:629-656`); `model_proxy` → REQUIRED NOT_RUN (`sales_evaluator.py:637-642`).

## HIGH-CONFIDENCE SOURCE GAPS

Only items that are genuinely **(b)** or **(c)**. None is (b) — no listed item lacks an implementation entirely.

**G1. `management.reproducibility` has no producer that can ever yield PASS (c) — blocks G‑8 管理総本山Gate PASS.**

Neither real acceptance target even declares `verify_seed_replay`, so today the signal is simply absent.
Owner: `開発版/source/CORE/phase3_run_evidence.py::_signals` (producer) — with `development_acceptance_targets/*/profile.json` needing a `verify_seed_replay` scenario, and `management_evaluator.py` needing to accept a broader scope (or the producer needing to emit one).

**G2. No reviewer/observer for the 30-second and 5-minute player phases (c) — blocks B‑5.1, D‑1.3, D‑1.4 and the Sales readability chain (D‑3.1).**
Missing capability: something that turns a recorded session (video/screenshots/state trace) into a **verdict or findings list** for the phase — the evaluator accepts nothing else (`sales_evaluator.py:348-379`). Today the producer deliberately refuses to produce one (`phase3_run_evidence.py:344-355`), and the production-side 30 s row is hard-coded `INCONCLUSIVE` (`windows_runner.py:417`).
Owner: `phase3_run_evidence.py::_phase_evidence` + `windows_runner.py` `if s.get('evaluation')` block — i.e. a new observer/analyser (or a human-review intake) whose output the evaluator can consume as `status`/`findings`.

**G3. `sales.human_test` is a REQUIRED gate with no non-automated source (c) — blocks G‑9 営業総本山Gate PASS.**
Missing capability: a human-review intake (reviewer identity, session, per-phase findings) and a documented merge path into the run evidence. The producer is hard-wired to `model_proxy` (`phase3_run_evidence.py:389-391`) and the evaluator refuses to promote a proxy (`sales_evaluator.py:637-642`); `coordinator.py:239-247` even revokes any `human_test_performed` claim that the Sales readback contradicts.
Owner: new human-review intake module (would feed `hq_evidence` via `extras.sales_evidence` or `evidence/sales_evidence.json`) + `sales_evaluator.py` phase contract.

**G4. Offline / Registry / Program Files permanence cannot be certified (c) — blocks A‑3.5, C‑3.4, C‑3.5.**
Missing capability: (i) continuous network isolation proof — the only observable is a passive adapter count and the project states “Full offline always remains NOT_RUN” (`local_acceptance_observer.ps1:64,156`; `LOCAL_OBSERVATION_LIMITS.md:14,19`); (ii) a Program Files write audit — no code anywhere references “Program Files” (`local_acceptance_observer.ps1:155` `status='NOT_RUN', reason='NOT_COLLECTED'`); (iii) a Registry write audit beyond the two `Environment` root values (`run_series.py:223` `registry_write_audit:'NOT_RUN'`).
Owner: `開発版/local_acceptance_kit/local_acceptance_observer.ps1` (+ `phase3_run_evidence.py::_network_adapter_snapshot`).

### (iii) The `Get-Content` asymmetry — **CONFIRMED exactly as hypothesised**

* Self-test read, **NO `-Encoding`** → inherits PS 5.1 `Default` = ANSI code page:
  ```
  404:  $source=Get-Content -LiteralPath $PSCommandPath -Raw
  408:  $normalizedSource=$source.Replace("`r`n","`n")
  412:  $live=$normalizedSource.Substring($mainIndex)
  425:  if (-not $live.Contains('开发版/transfer/TRANSFER_MANIFEST.json') …
  ```
* Manifest read, **DOES use `-Encoding UTF8`** (correct):
  ```
  695:  $transfer=Get-Content -LiteralPath $transferManifestPath -Raw -Encoding UTF8 | ConvertFrom-Json
  ```
  (same pattern in `PREPARE_SOURCE.ps1:42` and `RESTORE_PREDECESSOR.ps1:54`)

**Consequence:** under Windows PowerShell 5.1 the *script text* is decoded with the ANSI code page, so **both** sides of the `.Contains()` comparison at line 425 are the same mojibake string → the assertion is **vacuous**; it can never fail. Meanwhile the *live* path built at line 693 from the same mojibake literal points at a non-existent directory → `Test-Path` fails → `TRANSFER_MANIFEST_MISSING`.

This is not folklore; it is documented Microsoft behaviour. `about_Character_Encoding` (powershell-5.1 view):
> "Creating PowerShell scripts on a Unix-like platform or using a cross-platform editor on Windows, such as Visual Studio Code, results in a file encoded using `UTF8NoBOM`. These files work fine in PowerShell, but may break in Windows PowerShell if the file contains non-Ascii characters. … **Without the BOM, Windows PowerShell misinterprets your script as being encoded in the legacy "ANSI" codepage.**"
>
> "For cmdlets that read string data in the absence of a BOM: **`Get-Content` and `Import-PowerShellDataFile` uses the `Default` ANSI encoding. ANSI is also what the PowerShell engine uses when it reads source code from files.**"

# 5. Architecture decision

| ゾーン | 所有者 | 契約 | 禁止 |
|---|---|---|---|
| **repo**(`main`) | 権威Source + 契約 + CI | PS 5.1が実行する全`.ps1`は **ASCIIのみ or UTF-8+BOM**。宣言入力はmanifest/planから導出 | 非ASCIIリテラル、fingerprint実装の複製、ハードコード絶対Path |
| **source**(prepared tree) | 不変のビルド入力 | `prepared_source_fingerprint` は**全overlay完了後**に計算。Source回帰は入力を変更しない | overlay前のfingerprint、回帰による入力改変 |
| **candidate** | 凍結成果物 | `size`/`sha256` 固定。Run1前に `CANDIDATE_FREEZE.json`、Runごとに再検証 | runごとの再freeze、過去PASSの流用 |
| **workspace** | 一時・repo外・短縮ドライブ | runごとにfresh、終了時削除、入力にならない | repo内work、前run再利用 |
| **evidence** | 保全・repo外(sibling) | 書き込み後は不変、readback検証、Gate判定を含む | repo内保存、PASS/FAILによる削除 |
| **rollback** | 独立資格（seriesの後） | byte identity + 実行可能なpredecessor selftest | rollbackが他Evidence収集を阻害 |
| **real-machine acceptance** | 環境オラクル | offline / 非管理者 / 実ゲーム / 実GPU の事実のみ | **移植性(script portability)の判定** |

> **実機は最後のゲートであり、最初の判定装置ではない。**

# 6. Candidate freeze prerequisites

**freeze前に必ずSource側で閉じるべき項目。** 1件でも欠けていれば freeze後の実機Runは失敗し、**Candidate再freeze**が必要になる。

- **P0-1 PS 5.1 encoding契約**（最優先・3ファイル違反）: (a) ASCII化（PR #19方式の構造探索に寄せる）or (b) UTF-8 BOM付与。**推奨は両方**。hosted CI に「PS 5.1が実行する`.ps1`はBOMあり or ASCIIのみ」のgateを追加。*参照: PR #19 `ed15668` は "encoding-safe local completion path discovery — Remove non-ASCII path literals" として既に解決済み。**再導入ではなく復元。***
- **P0-2 `.ps1`からの非ASCIIリテラル除去**: runner 6箇所(425,693,722,723,744,853)、`PREPARE_SOURCE.ps1:40`、`RESTORE_PREDECESSOR.ps1:52`

- **P0-4 offline観測のfail-closed化（2箇所）**: adapterごとにアドレス取得成功件数を保持し失敗があれば全体NOT_MEASURED。`Get-NetIPAddress` 失敗を `up_adapter_count=0` として扱わないことをunit testで固定
- **P0-5 Management Gate の producer/evaluator 矛盾解消**: `management.reproducibility` は独立run間の再現性を要求。producer はrun内seed replayしか出せずevaluatorは拒否。**A-B-A level での独立run再現性を算出**、またはevaluatorが受容するscopeを追加。**required は削らない**

- **P0-8 Registry / Program Files / offline恒常性の観測器**: `local_acceptance_observer.ps1` と `run_series.py:223` を拡張。**失敗はNOT_MEASURED**

# 7. Final acceptance sequence

**Candidate は1つ。実機Runは1回。** Source 変更があればCandidateを再freezeし系列を最初から再開（`FINAL_SERIES_PLAN.json` の `target_update_policy: restart_series_after_candidate_profile_or_target_change` に一致）。

**F0 — hosted preflight（実機に出る前に全部閉じる）**
1. PS 5.1 encoding gate / 宣言入力解決 / Candidate build / rollback（実機同引数）が **緑**
2. Management/Sales observer の contract test が緑
3. `codegeas` storage locations 宣言済み
4. ここで **Candidateをfreeze**（`CANDIDATE_FREEZE.json` + size/sha固定）

**F1 — 実機の入手**: frozen commit の **fresh extraction**（overlay禁止、失敗runツリー再利用禁止）、標準ユーザー/非管理者/外部ネット切断

**F2 — `RUN_LOCAL_COMPLETION.cmd` を1回だけ**

| Stage | 内容 | 判定 |
|---|---|---|
| 0 | Handoff preflight（manifest駆動 / PS 5.1 実パス解決） | PASS/FAIL |
| 1 | preserved v0.3.3 donor JOIN + byte identity | PASS |
| 2 | Source再構築 → **overlay後** fingerprint → Candidate build + identity | PASS |
| 3 | fresh Candidate の bundled Source回帰 + **immutability** | PASS |
| 4 | fresh Candidate `START_QA.cmd -SelfTest` | PASS |
| 5 | fresh PoliticsTrasport → codegeas → PoliticsTrasport（3 fresh extraction / frozen target / 過去Run不使用） | 3/3 PASS + Result ZIP 3件 |
| 6 | preserved predecessor rollback（実機と同引数） | PASS |
| 7 | environment readback（非管理者/offline start・series・end/PATH/Registry/Program Files） | PASS or NOT_MEASURED（FAIL化しない） |

# 8. Things to stop doing

1. **handoff方式（overlay/fresh freeze）をblockerとして扱うことをやめる。** 2つのhandoffで同一エラーが出た時点で変数はhandoffではない。**変数は `84e7d1f`(2026-11-06 20:07)が再導入した非ASCIIリテラル**

3. **自己検査による自己検証をやめる。** `$live.Contains(<自身のリテラル>)` は恒真。**振る舞いをassert**（hosted CIで実パスを解決して一致確認）へ置換
4. **`Get-TreeFingerprint` を新しく複製しない。** 既に4定義。**1定義に畳んで他を削除**
5. **「次のblockerを見つけるためのCandidate再構築」をやめる。** Sourceが変わればCandidateが変わる。**Source動かさずに再freezeする理由はない**
6. **実機を「移植性の判定装置」として使わない。** 移植性はhosted CIのPS 5.1で判定、実機には環境事実だけを残す
7. **PR #29型のpreflightを実機で回さない。** CIのPS 5.1 gateとしてhostingする
8. **Management/SalesのNOT_RUNを「次回Runで解決される話」として扱わない。** observer設計の問題でありRun回数の問題ではない
9. **`Get-NetAdapter` の「0 up adapters」をoffline PASSとしない。** アドレス取得失敗をNOT_MEASUREDに直す（禁止事項への直接違反）
10. **Issue #1のchecked項目を「実装が存在する」だけで再確認しない。** 特に **G-8/G-9/A-3.5/C-3.4/C-3.5** はcheckedになるべきでない
11. **過去Candidate/A-B-AのPASSを新Candidateへ流用しない**（現状は正しく運用されている。**維持**）
12. **「ローカル修正→再実行」を改善 없이繰り返さない。** 次の修正は「どのhost gateを緑にするか」が定義されていなければ禁止

# 10. Final recommendation

## 次に何をするべきか（1本）

> **「実機実行契約（Windows PowerShell 5.1）を hosted CI の gate として作り上げる」ことを、1つの作業単位として完了させる。**
>
> 具体的には、PR #19 `ed15668` が解いた encoding-safe な入力解決（構造探索 or manifest 駆動）を**3スクリプトへ復元し**、overlay後の fingerprint 順序を直し、offline 観測を fail-closed にし、その3点すべてを **`shell: powershell`（PS 5.1）の hosted job で緑にする**。
> **それが緑になった後、Candidateを1つだけfreezeし、実機を1回だけ走らせる。**

### なぜこれが「1本」か

- 実機の3回の失敗は、**1つの原因（PS 5.1 + 非ASCIIリテラル）**の3つの表出であった
- その原因は **CI が PS 5.1 で実パスを一度も解決していない**ことに起因する
- したがって **「PS 5.1 で実パスを解決する hosted job」を1本作る**だけで、D1（解決）・D4（引数不一致）はまとめて消え、D2・D3も gate で塞がれる
- 現状で実機を走らせると **確実に次の境界で止まる**（D2は確定的）。**実機Runの回数を増やさないこと自体が成果**

### 同時に（同じ作業単位の一部として）片付ける3点

- **P0-5 / P0-6**: Management / Sales の到達不能を解消する観測器。これ無しでは Issue #1 のDoD（3総本山Gate）に**原理的に到達しない**
- **P0-7**: codegeas の storage locations。これ無しでは緑の実機Runが B-4.3 で落ちる
- **PR #27 の取り込み**（fingerprint正本化 + immutability契約）と **PR #29 の取り込み**（preflight概念）を **上2点のCI job の中に統合**

### やってはいけないこと（この1本の中）

- 実機の再走（green gateが立つまで）／Candidateの再freeze（Sourceが変わらない限り）／Issue #1のchecked項目の再確認（Evidenceなしの昇格は禁止）／Management・Salesのrequiredを落とすこと／proxyをhumanにすること

### 監査の限界（未検証部分）

- 失敗したhosted jobの**詳細ログは取得不能**（匿名でのjob log DLは `403 Must have admin rights`）。§3.1の「baseで赤 → PR #27 headで緑」は**前後の観測**でありログによる因果確認ではない
- 実機が生成したMojibake実バイトはLinuxから再現不能。結論はMicrosoftのdocumented behavior（`about_Character_Encoding`: BOM無しのスクリプトはANSI codepageと解釈／`Get-Content`の既定はANSI）+ 3回の同一症状から導出
- 実機の実ANSI codepageがCP932かCP1252かはリポジトリから観測不能。**いずれでも「一致しない文字列」が生成されるため結論は不変**
- Actions全923runの全量ではなく、main 32 run + 分岐run + 近期runを列挙
- Management/Salesの「required rowがAutomated runでPASSしうるか」は、忠実なbundleをCOREのproducer/evaluatorに投入して導出。**実機での再確認は未実施**
- `安定版/` は `README.md` のみで、Rollbackの対象はpreserved predecessor Candidateである点に注意（Issue #1 G-15の解釈に影響）
